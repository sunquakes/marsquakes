# 构建后台管理系统

六句话，按顺序说。每一句都有一个你可以检查的结果，不用读任何代码。

一个后台管理系统是一对**配套的**部分：你看到的网页，和背后存数据的后端。
分开来要，你会得到两个互不知道对方存在的项目——所以下面每一句提示词都把这两半当作一个整体来提。

:::tip 先做环境准备那一页
这一页假设你的电脑已经准备好了——见[后台管理环境准备](./ai-admin-env.md)。
:::

## 第 1 步 —— 创建项目

> **提示词**
>
> 在当前文件夹下创建一个叫 `admin-platform` 的项目。我只要后端和管理后台网页，
> 不要手机端、不要桌面端、不要门户网站。用 Marsquakes 那个工具来创建。

**你应该看到：** 确认创建了正好两个部分。

```
✅ Selected 2 modules:
   - Web Admin
   - API Service
```

然后问："你实际创建了哪几个目录？"答案应该只提到那两个。多出来的就是建错了——
说"删掉重新来，只要那两个"，不要试着把多余的去掉。

:::tip 这个组合是最简单的
后端加管理后台网页就是默认值，所以那个工具不需要停下来问任何问题。其他所有组合——
包括[桌面应用](./ai-desktop-prompts.md)——都会让它停下来问，Agent 必须回答，不能跳过。
:::

## 第 2 步 —— 安装项目需要的东西

> **提示词**
>
> 配好环境变量文件，然后安装这个项目需要的所有东西，包括后端自己需要的那些工具。
> 我在国内网络。在第一次启动任何东西之前，先把数据库密码填好。

提你在哪是有意义的——下载来源取决于你所在的地域，选错了，两分钟装完的东西会变成二十分钟的慢爬。

**你应该看到：** 项目根目录下有一个 `.env` 文件，密码已经填好了。安装全程没有报错。

Java 和 Maven 也是在这一步装上的——前提是你电脑上本来没有。它们在[配环境](./ai-admin-env.md#准备好了应该是什么样)
那一步是故意跳过的：在第 1 步把项目建出来之前，谁也不知道你要做后端。现在项目自己说了，
工具就能推导出来，不用你开口。

:::caution "Java 明明是好的，却说 JAVA_HOME 没设置"
这看着像坏了，其实没坏。跑这条命令的那个窗口是在 Java 装完之前打开的，所以它拿的是过期
信息。你说："重新开一个终端窗口再检测一遍，不要重装。"重装 Java 一点用都没有。
:::

:::note 安装卡住不是失败，是下载源不对
如果它看起来几乎不动了，那基本都是从地球另一边在下载。你说："换成适合我所在地区的下载源，
重新试一次。"不要干等着。
:::

## 第 3 步 —— 启动两个半端

你的项目**直接跑在你的电脑上**。只有数据库在 Docker 里。你改的任何东西都不进盒子。

> **提示词**
>
> 用 Docker 把数据库和缓存起起来，然后把后端和管理后台网页在我电脑的后台跑起来。
> 分别告诉我每个的访问地址。

**你应该看到：** 两个地址。管理后台网页是你打开浏览器要看的那个；后端在
`http://localhost:8080/jeecg-boot` 响应，它本来就不是用来在浏览器里看的。

不需要额外配什么——后端已经知道怎么找你刚启动的数据库了。

:::caution 要说"在后台跑"，不然 Agent 会看起来卡死
两个半端都会一直跑直到你停掉它们，这意味着 Agent 如果正常启动一个，就会一直坐在那里
什么也不给你看。说"在后台跑"然后要地址，才能避免这个问题。

两个相关的陷阱：

- 如果只启动**网页**那一端，你会看到一个登录界面，但点什么都报错。
  那不是 bug——只是后端还没跑而已。
- 笼统地说"把所有东西都启动起来"实际上覆盖不到后端，Agent 会回你一个莫名其妙的
  "no package named api"。要把两个半端都说清楚，就像上面那段提示词那样。
:::

:::caution 如果后端找不到数据库
Agent 有时候会把后端切到"容器模式"去匹配 Docker 里的数据库，那会让它去找一个只在
Docker 内部才存在的地址。如果后端报了一个"找不到主机"的错误，就说："关掉 docker profile，
用默认配置——我是直接跑在自己电脑上的。"
:::

## 第 4 步 —— 给两个半端加一个功能

这是你真正想做的部分。关键是**把三层都点出来**——漏掉任何一层，你得到的就是一个
屏幕上能看到但背后没有数据的列：

> **提示词**
>
> 先读 `apps/api/AGENTS.md` 和 `apps/web-admin/AGENTS.md`，然后给我一个方案再改。
> 我想在文章上加一个"发布"开关：存到后端里，列表接口返回时带上它，管理后台的表格里
> 显示为一列。改完把你动过的所有文件列出来。

**你应该看到：** 文件清单两边都有，同一个字段名出现在三个地方。只改了一边是这里最常见的失败——
如果文件清单只提到一个半端，就说："你只做了半，把另一半补上。"

两个值得养成的好习惯：

| 习惯 | 为什么 |
| ---- | ------ |
| 先要方案 | 纠正方案只要一句话，花一个下午去拆写错的代码就不划算了 |
| 一次只改一个功能 | 三个功能混在一次改动里，要撤回那个坏掉的就做不到了 |

## 第 5 步 —— 写下来

> **提示词**
>
> 把"发布"开关怎么做作为内部笔记写下来。然后在文档站上加一页面向读者的说明，
> 并且在侧边栏里注册。

有两个不同的地方用来写东西，Agent 总是搞混：

| 你写什么 | 放哪里 |
| -------- | ------ |
| 笔记、方案、给自己和团队看的记录 | `.docs/`——私有的，不对外发布 |
| 给读者看的页面 | `docs/content/`，**并且**要在 `docs/sidebars.ts` 里注册 |

**你应该看到：** 笔记在私有文件夹里，页面在公开文件夹里，还有一个新的侧边栏条目。
不在侧边栏里的页面，在文档站上根本不会出现，所以问："你加的是哪个侧边栏条目？"

然后说："构建一下文档站，告诉我是否通过了。"这个文档站故意配置成只要内部链接断了就
构建失败，所以构建通过是实打实的证据，不是安慰。

## 第 6 步 —— 打包给别人用

> **提示词**
>
> 把两个半端都构建成发布的版本，然后告诉我每个产物文件具体在哪。

**你应该看到：** 两个真实存在的文件路径。要具体路径——"构建成功了"你没法检查，
一个你能看到的路径才可以。

这是唯一一个正经用 Docker 来编译你的代码的时候——因为打包的那个人电脑上可能什么工具
都没装。这是交付用的路，不是开发时的捷径：还在改代码的时候用它，只会让每件事都变慢，
报错也更难读。

## 如果你后来又加了一个端

假设过了一个月，你想再加一个桌面应用，让别人不用打开浏览器也能用上这套东西。启用它这
件事是对项目的改动，而"需要哪些工具"是由项目决定的——所以启用之后，再让 Agent 做一次
安装那一步：

> **提示词**
>
> 给这个项目启用桌面应用，然后把它现在需要的东西装上。

**你应该看到：** 这次装的是 Rust，Java 不会再装一遍，因为它已经在了。

这也就是为什么一开始什么都没提前装。回到[配环境](./ai-admin-env.md)那一步的时候，谁
也不可能知道你以后会想要一个桌面应用，所以靠猜就只能"万一你要用"地把所有东西都装上。
改成问项目之后，就算你后来改了主意，答案也还是对的——你只要再让它安装一次。

## 这样说更好

| 别这样说 | 要这样说 |
| -------- | ------- |
| "建个项目" | "创建一个只有后端和管理后台网页的项目" |
| "修一下构建" | "文档站构建失败了——读一下错误，告诉我原因，然后修好它" |
| "加个表格" | "按 `apps/web-admin/AGENTS.md` 的约定加一个文章列表页" |
| "让它跑起来" | "用 Docker 把数据库起起来，然后把后端和管理后台网页跑在我电脑上" |

规律都一样：说你要什么，指出约束条件，指向约定文件，并且要一个你能看到的结果回来。

## 卡住了怎么办

你不需要诊断任何东西。找到你的症状，说那句话：

| 你看到什么 | 这样说 |
| ---------- | ------ |
| 安装卡住不动了 | "换成适合我所在地区的下载源，重新试一次" |
| 数据库报"拒绝访问" | "密码是在数据库第一次创建之后才改的。把数据卷删掉，重新建一个" |
| 前端构建每次报在不一样的样式文件上 | "检查最外层 AGENTS.md 里要求的那个构建配置——不要改版本锁定" |
| JVM 报了一个内存相关的错误，但你知道不是内存问题 | "这是最外层 AGENTS.md 里说的那个版本锁定问题。读一下那个文件，不要改锁定的版本" |
| 管理后台能打开，但点什么都报错 | "后端没跑。在后台启动它，告诉我它的地址" |
| 报了一个"no package named api" | "后端不是 workspace 工具管的——用它的方式启动" |
| 后端找不到数据库主机 | "关掉 docker profile，用默认配置——我是直接跑在自己电脑上的" |
| Agent 很久没动静了 | "你在等一个永远不会结束的东西吗？改成在后台跑" |
