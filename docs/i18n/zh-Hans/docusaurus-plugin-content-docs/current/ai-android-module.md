# 构建 Android 应用：创建功能

两句话。到这一步，[创建项目](./ai-android-project.md)里那个只能打开的应用，才会变成一个
**会做事**的应用。

:::tip 隔了一段时间再回来？
如果电脑重启过，先把手机连好或重新启动模拟器——改动只有装到设备上才能看到。
:::

## 第 1 步 —— 加一个功能

这才是你真正想做的事。关键是把**三个层**都说清楚——存东西的数据层、把两头连起来的
连接层、以及你看到的那个界面。漏掉一个，你就会得到一个背后什么都没有的界面。

你不需要知道这些层叫什么名字。项目把自己的约定写下来了，所以直接把 Agent 指过去：

> **提示词**
>
> 先读 `apps/android/AGENTS.md`，按里面的约定做，然后改任何东西之前先把计划给我看。
> 我要一个商品管理界面：能新增、编辑、删除商品，并且两种语言都能用。改完之后列出你
> 改过的每一个文件。

**你应该看到：** 大约十个文件改动。如果不到六个，说明有东西被跳过了——就说："你漏了
一层，重新看一下约定文件，把它补完。"

一定要在设备上打开应用，亲手试一下你刚要的操作。界面能显示、一按按钮就报错，通常就是
有一层只接了一半。

两个值得养成的习惯：

| 习惯 | 为什么 |
| ---- | ------ |
| 永远先要计划 | 纠正计划只要一句话，纠正改坏了的代码要一下午 |
| 一次只改一个功能 | 三个功能混在一个改动里，坏的那个就没办法单独撤销了 |

## 第 2 步 —— 写下来

> **提示词**
>
> 把商品界面是怎么用的写成一份内部笔记。

**你应该看到：** 笔记落在 `.docs/` 下面。那个目录是私有的，不会发布到任何地方。

如果它落到了 `docs/content/` 里，那 Agent 刚把你的私人笔记放到了一个公开网站上。就说：
"把那个文件挪到 `.docs/`——它不是给公众看的。"

功能能用、也写下来了，应用就算做完了。下一步：[打包](./ai-android-deploy.md)。
