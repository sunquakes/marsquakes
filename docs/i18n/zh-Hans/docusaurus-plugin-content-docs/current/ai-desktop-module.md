# 构建桌面应用：创建功能

两句话。到这一步，[创建项目](./ai-desktop-project.md)里那个空空的窗口才会变成一个
**能做事**的应用。

:::tip 隔了一段时间再回来？
如果电脑重启过，之前运行的东西都没了——让 Agent 把桌面应用重新启动起来，告诉你
窗口什么时候应该开好，然后再做这一步。
:::

## 第 1 步 —— 加一个功能

关键是要把**三层都点出来**——存东西的那一层、把两头连起来的那一层、你看到的那个界面。少一层，你得到的就是一个背后什么都没有的界面。

你不需要知道这些层叫什么：项目把自己的做法写下来了，直接把 Agent 指过去：

> **提示词**
>
> 先读 `apps/desktop/AGENTS.md`，按里面那套分步流程来，改任何东西之前先把方案给我看。
> 我要一个商品管理界面：我要能新增、编辑、删除商品，两种语言都要能用。做完把你
> 改了哪些文件列出来。

**你应该看到：** 大约 10 个改动文件。如果列出来少于 6 个，说明有东西被跳过了——就说："你漏了一层，再读一遍那个流程文件，把它补完。"

:::caution 那种看起来像成功了的失败
最常见的漏项是有个连接应用根本没登记上：做的时候什么都不报错，只有你点下按钮的一瞬间才报错。所以一定要亲手点一下你刚要的那个操作。如果报错了，就说："界面出来了但按钮点了报错——你写了代码但没把它接上去。"
:::

两个值得保持的习惯：

| 习惯 | 为什么 |
| ---- | ------ |
| 每次都先要方案 | 改一个方案只要一句话，把写坏的代码拆出来要一下午 |
| 一次只改一件事 | 三个功能混在一次改动里，你就没法只回退坏掉的那一个 |

## 第 2 步 —— 写下来

> **提示词**
>
> 把商品界面是怎么用的写成一份内部笔记。

**你应该看到：** 笔记落在 `.docs/` 下面。那个目录是私有的，不会发布到任何地方。

如果它落到了 `docs/content/` 里，那 Agent 刚把你的私人笔记放到了一个公开网站上。就说："把那个文件挪到 `.docs/`——它不是给公众看的。"

功能能用、也写下来了，应用就算做完了。下一步：[打包](./ai-desktop-deploy.md)。

## 卡住了怎么办

| 你看到什么 | 这样说 |
| ---------- | ------ |
| 界面出来了，但按钮一点就报错 | "你写了代码但没把它接上去，去正确登记一下" |
