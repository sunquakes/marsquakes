# 构建后台管理系统：部署上线

等[创建功能](./ai-admin-module.md)做出的系统在你自己电脑上跑通之后，三句话就够了
——打包、确认能用，再放到一台真正的服务器上，让别人也能通过互联网打开。

在之前的开发中，系统大部分直接跑在你电脑上，只有数据仓库跑在它的“盒子”里。部署
就是把**整个系统**——数据仓库、缓存、后台干活的服务和网页——打包在一起，让另一台
电脑什么都不用安装就能跑起整套东西。具体怎么实现你不需要懂，Agent 会按项目的标准
方式去做。

:::note 打包故意要花好几分钟
成品里的代码是在打包过程中编译的，这样它才能落到一台什么编程工具都没装的机器上。
还在改代码时不要走这条路；[在自己电脑上把它跑起来](./ai-admin-project.md)一直是
几秒钟的事，那才是日常开发用的。
:::

## 第 1 步 —— 把整个系统打包成“换台电脑也能跑”

> **提示词**
>
> 把整个后台管理系统打包成在一台什么都没装的电脑上也能运行的样子，然后把打包好的
> 版本跑起来。项目做这件事的标准方式通常需要的设置，你都按标准配上，包括在国内网络
> 环境下需要的那些。如果我已经开着的什么东西挡了路，你看着合理处理。让它一直跑着，
> 全部准备好了告诉我。

具体需要什么，Agent 心里有数：从你的源码构建两个应用、启动数据仓库和缓存、配好适合
本地区的下载源，再加一个让各部分互相找到的小文件。这些你一个字都不用敲。

**你应该看到：** Agent 告诉你打包好的系统已经跑起来了。底层有四个部分在运行，
如果你好奇或出了问题，可以让它把清单给你，确认正好是四个：

| 部分 | 机器上的地址（这些不用你打开） |
| ---- | ------------------------------ |
| 数据仓库 | 3306 |
| 缓存 | 6379 |
| 后台干活的服务（`jeecg-boot-system`） | 8817 |
| 管理网页（`jeecg-boot-web-admin`） | 8807 |

第一次打包要花好几分钟——打包时编程工具都在成品里面下载。长时间没动静是正常的；
报错才不正常。

:::caution 一个最容易漏的设置
数据仓库也跑在同一个打包好的系统里时，设置里必须让服务通过 `mysql` 和 `redis` 这
两个名字去找它们，而不是去找宿主机。设错了，服务会悄悄忽略刚启动好的数据仓库——
看着像网络问题，其实是设置问题。标准打包会处理好；留这条是为了万一出问题，你能
认出这个症状。
:::

:::note 第一次启动时重启是正常的
数据仓库第一次启动要把整个结构导进去，比服务预期的慢。服务起得太早、连接失败后会
自动被重新拉起，直到数据仓库能响应。重启几次是预期行为；一直重启停不下来才是故障。
:::

:::caution 先停掉开发时跑着的那几份
如果[创建项目](./ai-admin-project.md)时直接跑在你电脑上的系统还在运行，两份东西会
抢同一个地址。打包前先停掉那几份；已经待在盒子里的数据仓库可以继续跑——打包好的
系统会直接复用它。
:::

## 第 2 步 —— 打开它，确认能用

成品网页的地址是 `http://localhost:8807`。以 8817 结尾的地址属于后台干活的服务，
本来就不是给浏览器打开的——你唯一会用到的页面就是这个网页。

> **提示词**
>
> 打开打包好的管理网页，用我开发时一直用的账号登录。检查我们在
> [创建功能](./ai-admin-module.md)里加的“发布”开关还在，而且能用。

**你应该看到：** 登录页，然后是开发时看到的那些表格，包括你新加的那一列。打包好的
各部分通过自己的内部网络互相通信，不需要再配任何东西。

## 第 3 步 —— 放到真正的服务器上，任何人在任何地方都能打开

“跑在你电脑上”意味着只有你能打开。云服务器其实就是另一台一直开着、有公网地址的
电脑。

**租一台自带 Docker 的服务器（阿里云轻量应用服务器）：**

1. 打开产品页面并登录：[aliyun.com/product/swas](https://www.aliyun.com/product/swas)
2. 进入[轻量应用服务器控制台](https://swasnext.console.aliyun.com/servers/)，在左上角单击**创建服务器**。
3. 地域选离使用这套后台的人最近的。
4. 镜像类型选**应用镜像**（不是系统镜像），在列表里选 **Docker CE**。它开机就已经装好了 Docker 和 Compose，后面不用再单独安装。
5. 套餐选内存 2 GB 及以上的，确认购买数量和时长，单击**立即购买**并完成支付。
6. 回到控制台，等状态变成**运行中**，复制它的公网地址；在服务器卡片上**重置密码**，记下登录信息。

每一步的详细截图见官方文档：
[创建轻量应用服务器](https://help.aliyun.com/zh/simple-application-server/user-guide/create-a-server)，
可选的应用镜像见
[应用镜像概述](https://help.aliyun.com/zh/simple-application-server/user-guide/application-image)。

:::caution 域名指向国内服务器需要先备案
直接用 `http://服务器IP:8807` 这样的地址马上就能用。但要把域名指向国内服务器，
必须先通过阿里云做 ICP 备案，需要几天到几周。可以提前把备案办起来，期间先用
IP 地址。
:::

等拿到公网地址和登录信息后，把这些告诉 Agent，然后贴：

> **提示词**
>
> 我已经为本项目租好了阿里云轻量应用服务器，选的是 Docker CE 应用镜像，
> Docker 和 Compose 已经装好了。它的公网地址和登录信息是：［填在这里］。
> 把打包好的后台系统部署上去，让它在服务器重启后能自己启动，只开放网页需要的
> 端口，然后把要打开的地址给我。所有密码都不要和我本地用的一样。

**你应该看到：** Agent 告诉你系统已经在服务器上跑起来了，并给出一个地址，你用
任何电脑或手机都能打开。底层跑的还是同样四个部分；数据仓库和缓存从外面连不上
——只有网页这扇门是开着的。

:::note 域名和小锁放在“能用”之后
先用另一台设备确认 IP 地址能打开——比如用手机流量，而不是家里的 Wi-Fi。确认
之后再加域名，并让 Agent 给它配上 HTTPS（地址栏的小锁）。两件事一起做，会把
两个问题混成一个报错。
:::

## 卡住了怎么办

你不需要诊断任何东西。找到你的症状，说那句话：

| 你看到什么 | 这样说 |
| ---------- | ------ |
| 打包慢得像爬，或者像卡住了 | “把下载源换成适合我所在地区的镜像，从头再来” |
| 服务一直重启、报连不上数据仓库 | “检查数据仓库和缓存的主机名设置——在同一个打包好的系统里必须是 `mysql` 和 `redis`——然后重新启动” |
| 第一次启动重启几次，然后稳住了 | 不用做什么——等结构导完；只有一直停不下来才是故障 |
| 报“地址已被占用” | “停掉还直接跑在我电脑上的开发副本，或者在设置文件里改地址——别临时用别的办法改” |
| 网页每次都在不一样的样式文件上构建失败 | “检查最外层 AGENTS.md 里要求的那个构建设置——不要改版本锁定” |
| 报内存错误但你知道不是内存问题，或者数据仓库第一次启动就死 | “这是最外层 AGENTS.md 里说的版本锁定问题。读一下，别动锁定的镜像版本” |
| 拉取标准镜像失败或超时 | “给运行盒子的软件配上代理——继续用标准镜像，不要换成第三方的” |
| 改了密码之后数据仓库报“拒绝访问” | “密码只在存储空间为空时读取一次——把存下来的数据重置后重新开始，这会清掉里面原来的东西” |
| Agent 很久没动静了 | “看看你现在进行到哪一步了，告诉我此刻正在发生什么” |
| 手机上打开 IP 地址超时 | “检查服务器的防火墙——云控制台里的和机器本身的都查——再确认开机自启已经设好” |
| 服务器重启后网站就没了 | “把所有部分设成服务器重启后自动启动，然后重启一次验证给我看” |
| 国内服务器上域名解析不出来 | “ICP 备案还没下来——期间先用 IP 地址，别想办法绕过备案” |
| 浏览器提示网站“不安全” | “现在走的是普通 HTTP——先用 IP 地址确认能用，再去配 HTTPS 和小锁” |
