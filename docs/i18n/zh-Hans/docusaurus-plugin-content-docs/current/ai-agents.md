# Vibe Coding 在这里的工作方式

你用日常语言描述想要什么，Agent 来写代码、跑命令、把结果告诉你。你不需要敲命令，也不用
读代码——每一页都给你一句话去说，然后告诉你应该看到什么。

:::tip 你不需要看懂输出
Agent 打印的文字几乎都不是给你看的。只找本指南让你看的那几样——通常是一个网址、一个
文件路径，或者屏幕上弹出的窗口。
:::

## 值得养成的一个习惯

要一个**你能看到的结果**，而不是要一个动作。

| 别这样说 | 要这样说 |
| -------- | ------- |
| "把项目建起来" | "把项目建起来，然后告诉我能打开的网址" |
| "加一个商品页面" | "加一个商品页面，然后列出你改过的所有文件" |
| "打个包" | "打个安装包，然后告诉我安装包在哪" |
| "修一下" | "它报错了。读一下那个错误，告诉我原因，然后修好它" |

网址、路径或文件列表，就是你不读代码也能验收的依据。Agent 只说一句"好了"然后什么都
不给，你就没法检查。

### 各端的例子

| 别这样说 | 要这样说 |
| -------- | ------- |
| "建个项目" | "创建一个只包含网页版管理系统的项目" |
| "修一下构建" | "文档站构建失败了——读一下错误，告诉我原因，然后修好它" |
| "加个表格" | "按 `apps/web-admin/AGENTS.md` 的约定加一个文章列表页" |
| "让它跑起来" | "按标准方式把管理系统需要的一切都启动起来，页面可以打开了告诉我" |
| "建个桌面项目" | "创建一个只有桌面应用的项目——回答那个选择提问，挑 Desktop" |
| "把应用启动起来" | "把桌面应用启动起来，窗口开好了告诉我" |
| "加个商品页" | "按 `apps/desktop/AGENTS.md` 里那套分步流程，加一个商品界面" |
| "打个包" | "构建发布版本——我要一个安装包文件，告诉我它的确切路径" |
| "建个安卓项目" | "创建一个只有 Android 应用的项目——回答那个选择提问，挑 Android" |
| "装到手机上" | "把应用装到我连着的这台手机上，装好了告诉我" |

规律都一样：说你要什么，指出约束条件，指向约定文件，并且要一个你能看到的结果回来。

## 第一个项目：从零到跑起来

> **提示词**
>
> 我想在本地创建一个叫 `admin-platform` 的项目。我只要网页版的管理系统，
> 不要手机应用、不要桌面应用。建好之后告诉我你建了什么。

**你应该看到：** 一个简短的两行确认，说明它在建哪两个部分。

```
✅ Selected 2 modules:
   - Web Admin
   - API Service
```

这两个是默认组合。追问一句"你到底建了哪些部分"——答案应该正好是这两个，没有别的。
多了就说明建错了，现在重来比以后重来便宜得多。

> **提示词**
>
> 现在把项目需要的所有东西装上，然后启动起来。告诉我浏览器里打开的网址。

**你应该看到：** 一个网址，通常以 `http://localhost:` 开头。打开它，那就是你的项目
正在你自己的电脑上运行。

项目在你改动之前已经自动保存过一次历史。以后实验搞砸了，随时可以让 Agent 恢复原样。

## 要别的组合怎么办

默认组合是后端加管理后台前端。要别的东西——比如桌面应用——工具会停下来问你要哪些部分，
Agent 必须回答那个问题，而不是跳过它。你只需要按名字说出你要哪些：

> **提示词**
>
> 我只要桌面应用，不要别的。工具会问你要包含哪些部分。把它打印出来的列表读完，
> 找到标着 `Desktop` 的那一行，选标签，不要猜数字。

**你应该看到：** 一个确认信息，只包含你要的那一个部分。

```
✅ Selected 1 modules:
   - Desktop
```

:::caution 认标签，不要认数字
编号会随版本变化，告诉 Agent "选 6"迟早会选错——永远用标签名指定。标着
`[developing]` 的条目还没做完，选了也会被静默忽略。
:::

## 更多常用提示词

| 这样说 | 你会得到什么 |
| ------ | ------------ |
| "只启动管理网页" | 网站打开了，但每个页面都报错——因为整个系统还没跑起来 |
| "把整个系统启动起来" | 网页需要的一切都就绪，登录页能打开 |
| "打两个端的发布包" | 能交给别人的成品文件 |
| "把我的项目同步到最新模板" | 共用模板文件被刷新，你自己的代码不动 |
| "检查我的电脑缺什么，然后装上" | 一份缺什么的清单，然后开始安装 |
| "把系统需要的一切启动起来" | 它的数据仓库和缓存按标准方式启动，不需要你做任何选择 |

## 两个常记的规则

Agent 最容易搞错这两条。每次它要写文档或保存成果之前，直接贴这段：

```text
开始之前：先读离改动点最近的那份 AGENTS.md，按它说的做。给我的笔记和方案放 .docs/。
对外发布的页面放 docs/content/，并且必须在 docs/sidebars.ts 里注册。提交信息用英文。
```

## 卡住了怎么办

你不需要知道出了什么问题，把问题甩回给 Agent：

| 你看到什么 | 这样说 |
| ---------- | ------ |
| 它说"好了"但你什么都没看到 | "告诉我具体的网址，还有你创建了哪些文件" |
| 它卡住了，不再输出新内容 | "你是不是在等一个永远不会结束的东西？换一种不会耽误你跟我说话的方式启动，跑起来告诉我" |
| 报了一个你看不懂的错误 | "读一下那个错误，用大白话告诉我原因，然后修好它" |
| 它改的东西比你想要的多 | "列出你改过的所有文件和原因。我没让你动的全部撤销" |
| 你不确定它做得对不对 | "在改任何东西之前，先把你的方案给我看" |

:::tip 先要方案
一个错误的方案一句话就能纠正，一堆错误的代码要花一下午。超过小修小改，就说
"先把方案给我看"，你看完再让它动手。
:::
