# Vibe Coding 在这里的工作方式

你用日常语言描述想要什么，Agent 来写代码、跑命令、把结果告诉你。你不需要学任何命令。

这就是全部的规则。本系列的每一页都给你一句话去说，然后告诉你应该看到什么。
如果看到的不对，页面上也给了你下一句该说什么。

:::tip 你不需要看懂输出
Agent 会打印很多文字，其中几乎都不是给你看的。你只需要找本指南让你看的那几样东西——
通常是一个网址、一个文件路径、或者屏幕上弹出一个窗口。
:::

## 值得养成的一个习惯

要一个**你能看到的结果**，而不是要一个动作。

| 别这样说 | 要这样说 |
| -------- | ------- |
| "把项目建起来" | "把项目建起来，然后告诉我能打开的网址" |
| "加一个商品页面" | "加一个商品页面，然后列出你改过的所有文件" |
| "打个包" | "打个安装包，然后告诉我安装包在哪" |
| "修一下" | "它报错了。读一下那个错误，告诉我原因，然后修好它" |

要网址、路径或文件列表，是你不需要读任何代码就能验收工作的方式。
Agent 只说一句"好了"然后什么都不给，你就没法检查。

## 第一个项目：从零到跑起来

> **提示词**
>
> 我想在本地创建一个叫 `admin-platform` 的项目。我只要后端 API 和管理后台前端，
> 不要手机应用、不要桌面应用。建好之后告诉我你建了什么。

**你应该看到：** 一个简短的两行确认，说明它在建哪两个部分。

```
✅ Selected 2 modules:
   - Web Admin
   - API Service
```

这两个是默认组合，所以不需要手动选择。追问一句"你到底建了哪些模块"——答案应该正好是
这两个，没有别的。多了就说明建错了，现在重来比以后重来便宜得多。

> **提示词**
>
> 现在把项目需要的所有东西装上，然后启动起来。告诉我浏览器里打开的网址。

**你应该看到：** 一个网址，通常以 `http://localhost:` 开头。打开它，那就是你的项目
正在你的电脑上运行。

你的项目在你改动之前已经自动保存过一次了。所以如果后面的实验搞砸了，随时可以让 Agent
把东西恢复原样。

## 要桌面端怎么办

默认组合是后端加管理后台前端。如果你要别的东西——比如桌面应用——工具会停下来问你要哪些模块，
Agent 必须回答那个问题，而不是跳过它。

你不需要知道那个问题长什么样。你只需要说清楚你要哪些模块，并且按名字说：

> **提示词**
>
> 我只要桌面应用，不要别的。工具会问你要包含哪些模块。把它打印出来的列表读完，
> 找到标着 `Desktop` 的那一行，选标签，不要猜数字。

**你应该看到：** 一个确认信息，只包含你要的那一个模块。

```
✅ Selected 1 modules:
   - Desktop
```

:::caution 认标签，不要认数字
工具会打印一个编号列表，编号会随着版本变化。如果你告诉 Agent "选 6"，它迟早会选错。
永远用标签名去指定。有些条目标着 `[developing]`——那些还没做完，选了也会被静默忽略。
:::

## 更多常用提示词

| 这样说 | 你会得到什么 |
| ------ | ------------ |
| "只启动管理后台前端" | 网站打开了，但每个请求都报错——因为后端还没跑 |
| "启动后端" | 后端在 `http://localhost:8080/jeecg-boot` 上响应 |
| "打两个端的发布包" | 能交给别人的成品文件 |
| "把我的项目同步到最新模板" | 共用模板文件被刷新，你自己的代码不动 |
| "检查我的电脑缺什么，然后装上" | 一份缺什么的清单，然后开始安装 |
| "把数据库和缓存启动起来" | 数据库和缓存服务在后台跑起来 |

## 两个常记的规则

Agent 最容易搞错这两条，值得每次写提示词时多说一句。你不需要知道为什么，直接贴：

```text
开始之前：先读离改动点最近的那份 AGENTS.md，按它说的做。给我的笔记和方案放 .docs/。
对外发布的页面放 docs/content/，并且必须在 docs/sidebars.ts 里注册。提交信息用英文。
```

## 卡住了怎么办

你不需要知道具体出了什么问题，把问题甩回给 Agent 就行：

| 你看到什么 | 这样说 |
| ---------- | ------ |
| 它说"好了"但你什么都没看到 | "告诉我具体的网址，还有你创建了哪些文件" |
| 它卡住了，不再输出新内容 | "你是不是在等一个永远不会结束的东西？把它当后台任务跑，跑起来告诉我" |
| 报了一个你看不懂的错误 | "读一下那个错误，用大白话告诉我原因，然后修好它" |
| 它改的东西比你想要的多 | "列出你改过的所有文件和原因。我没让你动的全部撤销" |
| 你不确定它做得对不对 | "在改任何东西之前，先把你的方案给我看" |

:::tip 先要方案
一个错误的方案一句话就能纠正。一堆错误的代码要花一下午。超过小的改动，就说
"先把方案给我看"，你看完再让它动手。
:::
