# 准备电脑：后台管理系统

**后台管理系统**就是那种你登录进去管东西的网站——管商品、管订单、管用户、管文章。
它分两半：你看到的那个网页，和背后存数据的那部分。

这一页是无聊的部分：确认你的电脑上有项目需要的那些程序。你一个都不用自己装。
你说一句话，Agent 去做。

## 什么跑在哪里，以及为什么值得知道

这一页只有一件事值得你理解，因为后面 Agent 做的大部分事情都由它决定：

| 部分 | 跑在哪 | 说人话 |
| ---- | ------ | ------ |
| 数据库 | **Docker** 里 | 一个现成的盒子，你永远不用打开它。万一它乱了，把盒子扔掉重来只需要一句话 |
| 你自己的项目 | **直接跑在你电脑上** | 这是你要改的部分。直接跑，才能让你的改动立刻看到 |

:::info 开发的时候，你自己的代码不进盒子
这里的 Docker 只是一个跑数据库的方便办法。如果哪个 Agent 建议在你还在改代码的阶段
把项目放进 Docker，拒绝它——那会让每个改动都要等更久才能看到，报错也会变得难读得多。
Docker 是最后一步的事，等你要把成品交给别人的时候才用。见
[第 6 步](./ai-admin-prompts.md#第-6-步--打包给别人用)。
:::

## 这样说，让它把环境配好

```text
把这台电脑配置成能开发 Marsquakes 后台管理系统。现在只装基础的那几个，后端自己的工具
等项目建好了再说。数据库用 Docker 跑，项目本身直接跑在我的电脑上。在装任何东西之前，
先告诉我缺了什么。
```

配环境就这一步。装什么、按什么顺序装、你的操作系统该怎么装，Agent 都已经知道了——
你不需要给它清单。

**你应该看到：** 先是一份"你的电脑缺了什么"的清单，然后是安装过程，最后再检测一遍，
确认现在都有了。

:::tip 安装程序跑完了，不等于装上了
安装程序可以顺利跑完，却什么有用的都没装上。真正算数的是第二遍检测——之前显示"缺失"
的那一项，现在变成了"找到"。Agent 如果跳过了这一步，就跟它要："再检测一遍，把结果给我看。"
:::

## "准备好了"应该是什么样

这里不会"先装着再说"。这一步只把每个 Marsquakes 项目都必须的那几个程序装到你的电脑上，
不管你要做什么：

| 程序 | 必须是 | 如果比这个老 |
| ---- | ------ | ------------ |
| Node.js | 22.12.0 或更高 | Marsquakes 工具本身跑不起来 |
| pnpm | 9.0.0 或更高 | 安装项目的各个模块会失败 |
| git | 2.20.0 或更高 | 项目创建不了 |
| Docker | 20.10.0 或更高 | 数据库根本起不来 |
| Docker Compose | 2.0.0 或更高 | 这是硬失败，不是警告——`1.` 开头的版本读不了这个项目的文件格式 |

后端自己的工具——Java 和 Maven——**故意不在这个清单里**。它们只有等项目建好、明确说
自己有后端之后才有意义，所以会在[第 2 步](./ai-admin-prompts.md#第-2-步--安装项目需要的东西)
里装。如果 Agent 现在就想装它们，你就说："先不装，等项目初始化的时候再装。"

如果某一项是"太老"而不是"没有"，就说："这个版本太老了，换成支持的版本，不要绕过去。"

:::note 为什么 Docker 在清单里，Java 不在
Docker 在这里是因为*这一页*已经决定了要用 Docker 跑数据库——这是你做的选择，不是从项目
推导出来的。Java 和 Maven 取决于项目里有什么，而目前谁也不知道。
:::

## 启动数据库

> **提示词**
>
> 用 Docker 把这个项目的数据库和缓存起起来。两个都确认健康之后，再做别的事。

:::warning 密码必须第一次就填对
数据库只记住它**第一次**启动时的密码，之后你怎么改它都不看。这一步弄错的后果是一个
"拒绝访问"的错误，而唯一的修法是把数据库删掉重建——里面存的东西也一起没了。所以在提示词
里加上这句："第一次启动任何东西之前，先把数据库密码写进 `.env` 文件。"
:::

**你应该看到：** Agent 报出两个部分都是 `running`。如果有一个一直在反复重启，说明它第一次
启动就失败了。你说："从头读一遍那个容器的日志，告诉我第一条错误是什么。"真正的原因，
早在你能看见的那条重复提示之前就滚过去了。

这之后什么都不用配。项目本来就是照着数据库现在的位置去找它的。

## Agent 不该"顺手改好"的东西

这个项目故意锁定了一些版本。它们看着过时，一个想帮忙的 Agent 会主动提出升级。
而这两种情况的报错都会把责任推给完全不相干的东西——一个报的是内存问题，另一个报的是
数据库损坏——所以你根本猜不到真实原因。

细节你不需要知道。你需要的是让 Agent 知道它不该碰：

```text
在改这个项目里任何东西之前，先读最外层的 AGENTS.md，然后告诉我它规定了哪些版本和构建
配置不能动。
```

**你应该看到：** Agent 点出几个具体的版本锁定和一项构建配置，并且说明它不会去碰。
说不出来就是没读过那个文件——而它迟早会去"修"其中一条。你说："认真读一遍那个文件，
重新回答。"

还有两句话值得提前交代：

```text
数据库地址那类配置不要动，我的项目是直接跑在我自己电脑上的。
如果下载失败，去 Docker 自己的设置里配代理，不要换成别的下载源。
```

第一句是因为项目里有些配置看着像数据库地址，其实只在项目被打包进 Docker 之后才生效；
Agent 在你还在开发的阶段改了它们，后端会坏，而报错不会告诉你原因。
