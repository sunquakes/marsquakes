# 准备电脑：桌面应用

**桌面应用**就是一个装在电脑上、有自己的窗口的真程序，不是在浏览器里打开的。它自己管自己的数据，不需要旁边再跑别的东西。

因为它要生成一个真正的、给对应操作系统用的程序，所以它需要一些网站不需要的构建工具。你不用自己装——一句话就能搞定。

:::danger 这个必须在你自己的电脑上构建
Windows 的应用只能在 Windows 上构建，macOS 的只能在 macOS 上。没有捷径。如果 Agent 说可以把它放进 Docker 来跳过这一步，那是不行的——拒绝它，让它老老实实装工具。
:::

## 这样说，让它把环境配好

```text
把这台电脑配置成能开发 Marsquakes 桌面应用。装好 Rust 工具链和我的操作系统需要
的构建工具。在装任何东西之前，先告诉我缺了什么。
```

Agent 已经知道你的操作系统需要什么，你不需要自己列清单。

**你应该看到：** 先看到一个缺了什么的清单，然后装东西，然后再次检测确认每一样都装好了。

:::tip 安装程序跑完了，不等于装上了
如果 Agent 跳过了第二次检测，就说："再检测一次，把结果报给我。"一样东西从"缺"变成"有了"，才是唯一算数的证据。
:::

## "准备好了"应该是什么样

你不需要知道这些都是什么。你需要 Agent 确认下面四样齐了：

| 程序 | 必须是 |
| ---- | ------ |
| Rust | `1.77.0` 或更高 |
| Cargo | 有，且能报出一个版本号 |
| Node.js | `22.12.0` 或更高 |
| 你的操作系统的构建工具 | 齐了——见下表 |

:::note 如果 Rust 报出来太旧
有些操作系统自带的 Rust 版本对这个项目来说太旧了。如果 Agent 报出来的版本低于 `1.77.0`，就说："那是系统包管理器装的，太旧了——用 rustup 装一份正确的。"
:::

:::caution 刚装完却报 Cargo 找不到
这看起来像是装坏了，其实不是。那个终端窗口是在装好之前打开的，所以它看到的信息是旧的。说："开一个新终端窗口再检测一次，别直接重装。"
:::

## 各宿主机的系统依赖

| 你的电脑 | 会装什么 | 装完之后应该看到 |
| -------- | -------- | ---------------- |
| Windows | 微软的构建工具——浏览器组件在 Windows 10 及以上自带 | 编译器有响应，而不是"无法识别" |
| macOS | 苹果的命令行开发者工具 | 一个路径，例如 `/Library/Developer/CommandLineTools` |
| Linux | 一组系统图形库和网页库 | 每一样都报出一个版本号 |

这些包名会随 Tauri 版本变化，所以最好让 Agent 去看官方列表，别让它自己猜：

```text
读一下 https://v2.tauri.app/start/prerequisites/ ，把里面针对我这个操作系统
列出的包装上。
```

**你应该看到：** Agent 报出它装了哪些包，并且和那个页面上针对你的电脑列出的一致。

## 不需要额外启动数据库

跟后台管理系统不一样，这里没有单独的数据库要跑。这个应用把数据存在一个文件里，第一次启动时自己创建，不需要任何东西在后台跑着。没有需要再准备的东西了。

如果以后你需要一个多个人同时用的共享数据库，告诉 Agent 它会帮你切换——到那时 [后台管理环境](./ai-admin-env.md) 就又有用了。
