# 构建桌面应用

按顺序说六句话。最后你会得到一个安装包文件，可以发给别人，别人双击就能装。

桌面应用是一个整体，不是两半。没有单独的后端要启动，没有数据库要跑，也没有什么要在浏览器里打开——这个应用就是你屏幕上的一个窗口。

:::tip 先做环境准备那一页
本页假设你的电脑已经准备好了——见[桌面应用环境](./ai-desktop-env.md)。
:::

## 第 1 步 —— 创建项目

> **提示词**
>
> 在这个目录里新建一个叫 `my-desktop` 的桌面应用。我只要桌面应用——不要后端，
> 不要管理后台网站，不要手机应用，不要对外网站。工具会停下来问你要创建哪些部分：
> 把它打印出来的列表读完，挑写着 `Desktop` 的那一行。

跟后台管理系统不一样，这个组合不是默认的，所以工具会停下来问你一个问题。Agent 必须真的去回答它。

**你应该看到：** 一条确认信息，只有一个部分。

```
✅ Selected 1 modules:
   - Desktop
```

然后追问一句："你实际创建了哪些部分？"答案应该只有桌面应用。如果冒出了别的东西，说明 Agent 跳过了那个提问而不是回答它——就说："删掉重做一遍，这次要回答那个选择提问。"

:::caution 认名字，别认编号
那个列表是带编号的，但列表一变编号就会跟着挪，所以别人告诉你的编号迟早会指错东西。永远让 Agent 把列表读完，挑标着 `Desktop` 的那一行。
:::

## 第 2 步 —— 安装项目需要的东西

> **提示词**
>
> 把配置文件按模板准备好，把这个项目需要的东西都装上。我在中国大陆。

说清你在哪很重要。不同国家的下载源不一样，选错了会把几分钟的安装变成漫长的等待。

**你应该看到：** 项目最外层出现一个配置文件，安装过程没有报错就结束了。

然后追问一句："桌面应用自己的代码目录在不在？"如果 Agent 说不在，那说明应用根本没被创建出来，你得回到第 1 步。

这里没有数据库步骤。这个应用把数据存在一个文件里，第一次运行时自己创建。

## 第 3 步 —— 启动它，看一眼

> **提示词**
>
> 把桌面应用用开发模式在后台启动起来，然后告诉我窗口什么时候应该开好了。

**你应该看到：** 你的屏幕上真的弹出一个窗口。那个窗口就是这个应用。从现在开始，你每要一个改动，这个窗口会在几秒内自己更新——你不用重启任何东西。

:::caution 要说"在后台跑"，不然 Agent 会看起来卡死
这个应用会一直跑到你关掉它为止，所以把它当普通步骤跑的 Agent 会一直挂着，什么话也不说。要求它在后台跑，就是为了避免这种情况。
:::

:::note 一片白的窗口不是崩溃
那说明应用起来了，但负责画界面的那部分还没跑起来。就说："窗口是白的——画界面的那个服务真的在跑吗？"
:::

## 第 4 步 —— 加一个功能

这才是你真正想做的事。关键是要把**三层都点出来**，因为少一层你就会得到一个背后什么都没有的界面——存东西的那一层、把两头连起来的那一层、以及你看到的那个界面。

你不需要知道这些层都叫什么。这个项目把自己的做法写下来了，所以直接把 Agent 指过去：

> **提示词**
>
> 先读 `apps/desktop/AGENTS.md`，按里面那套分步流程来，改任何东西之前先把方案给我看。
> 我要一个商品管理界面：我要能新增、编辑、删除商品，两种语言都要能用。做完把你
> 改了哪些文件列出来。

**你应该看到：** 大约 10 个改动文件。如果列出来少于 6 个，说明有东西被跳过了——就说："你漏了一层，再读一遍那个流程文件，把它补完。"

:::caution 那种看起来像成功了的失败
最常见的漏项是有个连接应用根本没登记上。做的时候什么都不报错，只有在你点那个按钮的一瞬间才会报错。所以一定要点一下你刚要的那个东西。如果它报错了，就说："界面出来了但按钮点了报错——你写了代码但没把它接上去。"
:::

两个值得保持的习惯：

| 习惯 | 为什么 |
| ---- | ------ |
| 每次都先要方案 | 改一个方案只要一句话，把写坏的代码拆出来要一下午 |
| 一次只改一件事 | 三个功能混在一次改动里，你就没法只回退坏掉的那一个 |

## 第 5 步 —— 写下来

> **提示词**
>
> 把商品界面是怎么用的写成一份内部笔记。

**你应该看到：** 笔记落在 `.docs/` 下面。那个目录是私有的，不会发布到任何地方。

如果它落到了 `docs/content/` 里，那 Agent 刚把你的私人笔记放到了一个公开网站上。就说："把那个文件挪到 `.docs/`——它不是给公众看的。"

## 第 6 步 —— 打包给别人用

> **提示词**
>
> 把桌面应用构建成正式的发布版本，然后告诉我安装包文件到底在哪。

**你应该看到：** 一个真实的文件路径，后缀是你电脑对应的那种安装包——Windows 上是 `.msi` 或 `.exe`，macOS 上是 `.dmg`，Linux 上是 `.deb` 或 `.AppImage`。一定要问路径："构建成功了"这句话你没法验证，一个你能打开看的文件才行。

那个文件就是你发给别人的东西。别人不需要装你装过的任何工具。

:::note 这一步没有捷径
跟后台管理系统不一样，这个应用没法在 Docker 里打包——它必须在一台真实的电脑上构建，而且要和你要发给的那些人用同一类电脑。如果 Agent 开始找 Docker 的做法，就说："桌面应用没有 Docker 这条路，直接构建。"
:::

## 这样说更好

| 别这样说 | 要这样说 |
| -------- | -------- |
| "建个桌面项目" | "创建一个只有桌面应用的项目——回答那个选择提问，挑 Desktop" |
| "把应用启动起来" | "把桌面应用在后台启动起来，窗口开好了告诉我" |
| "加个商品页" | "按 `apps/desktop/AGENTS.md` 里那套分步流程，加一个商品界面" |
| "打个包" | "构建发布版本——我要一个安装包文件，告诉我它的确切路径" |

套路永远一样：说清你要什么，把限制条件讲出来，指向规则文件，然后要一个你能看得见的东西回来。

## 卡住了怎么办

你不需要自己诊断。找到你看到的现象，把对应那句话说出去：

| 你看到什么 | 这样说 |
| ---------- | ------ |
| 多创建了别的部分，不只是桌面应用 | "你跳过了那个选择提问。删掉重做，这次要回答那个列表" |
| 启动应用时报 command not found | "开一个新的终端窗口再试——这个窗口里的信息是旧的" |
| 窗口开了但一片全白 | "窗口是白的——画界面的那个服务真的在跑吗？" |
| 界面出来了，但按钮一点就报错 | "你写了代码但没把它接上去，去正确登记一下" |
| 构建每次报在不一样的样式文件上 | "去看最外层 AGENTS.md 里要求的那个构建配置——不要改锁定的版本" |
| Agent 很久没说话了 | "你是不是在等一个永远不会结束的东西？改成在后台跑" |
| Agent 开始找 Docker 的构建办法 | "桌面应用没有 Docker 这条路，直接构建" |
